### 2.5 真实仓库扫描结果（ACC-02-08）

| 指标 | 结果 |
| --- | --- |
| 仓库 | `Z:\Game`（240 个顶层目录） |
| 档案总数 | **273 条**（folder=220 / archive=53） |
| 耗时 | **3.8 秒** |
| 警告 | 0 |
| 取消 | 否 |

**关键观察：档案数 273 > 目录数 240**，原因是容器目录会被下探：

- `AC585020` → 下探出 4 条档案（`②認証回避パッチ` / `③` / `④` / `⑤アップデートファイル1.01`）
- `RJ01038880` → 下探出 `hxcy` / `southplus` 两条

这符合 D5（智能下探）+ D15（每版本各建一条）的既定口径，但**是否符合你的直觉需要你实机判断**：

- 若你期望"`AC585020` 整体算一个游戏" → 需要改容器下探策略（例如：容器目录下若只有一个子目录含游戏，则提升为一条档案）
- 若你期望"这些 DLC/补丁各自独立" → 当前行为正确

**性能方面是好消息**：3.8 秒扫完 240 目录，远好于此前"HDD 上可能分钟级"的风险预估——因为按需下探 + 只读元数据（不读 exe 内容、不递归压缩包）。

## 6. 已知风险

| 风险 | 说明 |
| --- | --- |
| 网络盘探测慢 | `check_repository` 每次真探测，NAS 掉线时可能卡 1-3 秒（SMB 超时） |
| 断点续扫粒度 | 最小单元是顶层条目，单条目内部不可中断（规格允许） |
| 大仓库内存 | 扫描结果全量在内存累积，240 目录规模无问题；上万条目需分批（v2 优化） |
| 中文主机名 | 已实测不可用于 SMB（`\\珱垣的mini终端\资源盘` 不可达），实际只有盘符/IP 生效 |
