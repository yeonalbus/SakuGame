## 2. 阶段划分

> 每阶段完成即 `cargo test`（或 `vue-tsc`）通过 + 一条 commit。**P1–P4 必须在同一分支连续推进**（中途编译不过属正常，P4 结束才整体可用）。

### P1 数据层（schema v2 + 模型）

**范围**

1. `db.rs`
   - `SCHEMA_VERSION = 2`
   - 新表：`games` / `game_versions` / `game_version_executables` / `game_version_files` / `blocklist`（DDL 见技术规格 §5）
   - 迁移逻辑：`PRAGMA table_info(games)` 不含 `layout` → 判定为 v1 旧库 → `DROP` 旧业务表（含 v1 残留 `game_files`）→ 建新表；写 `schema_version=2`
   - `settings` 写入默认 `root_excluded_dirs`（JSON 数组）
2. `models.rs`
   - `GameLayout { Compact, Standard }`（`as_str` / `parse`）
   - `VersionSource { Scan, Manual }`（同上）
   - `ExeCandidate`、`VersionEntry`、`GameEntry`（两层）、`ScanWarnings`、`ScanReport`
   - DTO：`GameRow`（去掉 `group_key` / `game_type`，加 `layout` / `version_count` / `selected_version_id` / `selected_version_label`）、`GameVersionRow`、`ExecutableRow`、`GameDetail { row, versions, absolute_path }`、`BlocklistRow`、`ScanSummary`（加 warnings 明细）
   - 删：`ScanOutcome`、`ScanDelta`（v1 遗留）
3. `error.rs`：新增 `VersionNotFound(i64)` / `ExecutableNotFound(i64)` / `BlocklistNotFound(i64)`

**完成判定**：`cargo check` 通过（此时 scanner/store/commands 会因类型变更报错，**P1 只要求 db/models/error 自身无误**，整体编译在 P4 恢复）。

**commit**：`feat(db): 升级 schema 至 v2（游戏/版本/可执行文件/黑名单）`

### P2 扫描器（两层枚举）

**范围**：`scanner.rs` 重写

1. **删除**：`walk_dir` 递归、`ScanOutcome`、`max_depth` 配置、`ControlSignal` 之外的下探逻辑
2. **保留**：`list_dir`、`is_reparse`、`extend_path`、`normalize_rel`、`display_name_of`、`strip_archive_ext`、分卷匹配器、`is_archive_ext`、`is_excluded_exe`、`ScanControl`
3. **新增**
   - `ScanConfig` 加 `root_excluded_dirs: Vec<String>`（支持 `*` 简单通配，大小写不敏感），删 `max_depth`
   - `classify_game(dir, rel, config, warnings) -> GameEntry`（技术规格 §4.1 伪代码）
   - `scan_repository` 改为「枚举根的一级条目 → 目录排除 → `classify_game`」；根下散落压缩包计入 `warnings.root_loose_files`
   - `scan_one_game(root, game_relative_path, config) -> AppResult<GameEntry>`（单档案重扫）
   - `truncated_with_version_dirs` 统计（紧凑型且子目录含 exe/压缩包）
4. **测试**：新增 T-1.1-01～11、T-1.1-21～22（技术规格 §9）；**删除** `t3_depth_limit`、`t9_archive_not_through_subdir`；`t32` 改造为 T-1.1-02

**完成判定**：`cargo test scanner` 全绿（此时 store/commands 仍红，全量 test 在 P4 后）。

**commit**：`refactor(scanner): 改为两层枚举模型，退役递归下探与深度上限`

### P3 持久化（重扫保护）

**范围**：`store.rs` 重写

1. `apply_report(db, repository_id, report: &ScanReport, mark_missing: bool) -> (added, updated, missing)`
   - 逐游戏 upsert（`games`：保护 `display_name` / `game_code` / `cover_path` / `selected_version_id`）
   - 逐版本 upsert（`game_versions`：保护 `display_name` / `note`；`source='manual'` 的版本**不会**被扫描结果删除）
   - 扫描来源可执行文件全量替换；`manual` 来源保留；`is_selected` 保留、文件不存在则 `invalid=1`
   - `game_version_files` 全量替换
   - 黑名单命中：`game` → 整条跳过；`version` → 该版本跳过
   - `mark_missing`：本次未出现的游戏/版本标 `missing`（**不删除**）
2. `apply_single(db, game_id, entry: &GameEntry) -> (added, updated, missing)`（单档案重扫，走同一套保护规则）
3. **选中版本修复**：`selected_version_id` 指向的版本已不存在 → 置 `NULL`（读取时也做一次校验）
4. **测试**：T-1.1-11～15、T-1.1-17、T-1.1-20（本机 DB 级）

**完成判定**：`cargo test store` 全绿。

**commit**：`feat(store): 两层结构幂等落库与重扫保护`

## 3. 关键实现约定（施工时不得偏离）

| # | 约定 | 理由 |
| --- | --- | --- |
| 1 | 扫描只调 `list_dir` **两层**（游戏目录 + 各候选子目录），**绝不递归** | 对象定义：版本层下不下探 |
| 2 | `version_label` = 目录原名（扫描刷新）；`display_name` = 用户可改（不覆盖） | 重扫保护矩阵 §6 |
| 3 | 可执行文件路径一律**相对仓库根**存储 | 手动版本可指向版本目录之外 |
| 4 | 紧凑型 = 1 个版本（版本 `relative_path` == 游戏 `relative_path`） | 截断规则 |
| 5 | 版本 `game_type`：目录直接文件有候选 exe → `folder`，否则 `archive` | exe 优先（Q-G） |
| 6 | 无版本层继承 —— 标准型 0 版本合法 | 反例结构 |
| 7 | 黑名单优先级 > missing > 扫描 | §7.1 |
| 8 | `selected_version_id` 无外键，读写时校验修复 | 避免悬空 |
| 9 | 单档案重扫与全量扫描共用 `ScanSlot` | D9（珱垣确认） |
| 10 | `game_code` / `cover_path` 扫描器**永不写入** | D19 边界 |

## 5. 风险与回滚

| 风险 | 应对 |
| --- | --- |
| 旧库清空引发数据丢失 | 仅在 MVP 阶段可接受（珱垣确认不迁移）；`db.rs` 清表前在日志中打印提示；首次启动 UI toast 提示「已升级到 v1.1，请重新扫描」 |
| 排除名单导致某版本消失（唯一 exe 是工具） | 该子目录不构成版本 → 用户手动新建；验收时用 T-1.1-21 固化该行为 |
| NAS 上两层枚举的 IO 特征变化 | P6 对照 v1 实测 240 目录耗时；如显著变慢再议 |
| 前端重写导致既有交互丢失 | 逐项对照旧 UI 行为（编辑、封面、返回、toast）在 P5 自检清单中确认 |
| 中途需要回到 v1 | 每个阶段独立 commit；回滚 = `git revert` 到 P0 提交（`c94965c` 之后） |
