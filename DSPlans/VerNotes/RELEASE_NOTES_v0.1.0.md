# SakuGame v0.1.0

> **首个版本**（内部里程碑 MVP v1「扫描建档」与 MVP v1.1「两层结构 + 版本管理」合并）。
> **本版主题**：把「扫描建档」这一件事做扎实——从「能扫出游戏」升级为「能正确表达一个游戏的多个版本」。
> **数据结构**：v1 → v1.1 为**破坏性变更**（不迁移）。首次启动会清空既有档案，需重新扫描。
> **发布状态**：仅打 tag 留档，未对外发布 GitHub Release。

## ✨ 新增功能

- **两层仓库结构**（`仓库根 / 游戏标识层 / 版本标识层 / 内容`）：
  - 仓库根下的每个直接子目录 = 一个游戏档案；
  - 其直接子目录 = 该游戏的版本（仅当该子目录**自身直接**含可执行文件或压缩包时才算版本）；
  - 单版本游戏可用紧凑形态 `仓库根 / 游戏名或编号 / 内容`。
  - 版本层名称**不做语义解析**（`Ver1.0`、`v2`、`更新版`、`2024春` 等价），系统只数层级。
- **建档断言**：仓库根下每个直接子目录**必定**建档，与内部是否有可执行文件无关。取舍遵循「宁可多一条可删的档案，不允许漏掉一个游戏」。
- **版本管理**（详情页 → 版本管理 tab）：版本列表（可折叠）、版本显示名与备注、版本类型（文件夹 / 压缩包）、手动 / 扫描来源标记、版本删除。
- **启动项配置**：每个版本可列出扫描到的候选可执行文件并选定其一作为启动项；启动按钮的下拉列表**只列出已配置启动项的版本**。
- **手动新建版本**：为不符合规范的目录手动指定「版本目录 + 启动项」，启动项允许指向版本目录**更深层**（用于兜底 `Game/data/game.exe` 这类结构），不需要移动文件。
- **档案 / 版本删除 + 黑名单**：删除后写入黑名单，重扫不再判定；设置页按档案分组折叠展示，**取消拉黑立即恢复**（档案 → 主页，版本 → 所属档案）。
- **单档案重扫**：详情页按钮，只刷新单个档案；占用全局扫描槽，与全量扫描互斥。
- **扫描可见性告警**：仓库根下散落文件、被截断目录的子目录、目录枚举失败，扫描结束后在设置页展示明细。

## 🛠️ 优化改进

- **扫描模型重写**：递归下探 + 深度上限 3 退役，改为两层枚举。单次扫描对每个游戏目录只做「自身 + 各候选子目录」两次列目录，IO 行为可预测。
- **真实仓库性能**（`Z:\Game`，240 顶层目录）：档案 240 条 / 版本 253 条 / 耗时 **12.8 秒**；同时**目录枚举失败从 44 降为 0**（不再深递归 + 长路径处理）。
- **卡片墙按游戏聚合**：同一游戏的多个版本只显示一张卡，右下角显示版本数角标。
- **黑名单语义修正**：删除档案只写 1 条档案记录，不再级联写其下版本（档案被拉黑后其版本目录自然不会参与扫描）；已单独拉黑的版本记录保留，恢复档案时可继续排除。
- **详情页交互**：名称 / 编号改为图标化内联编辑，封面改为右上角角标更换，移除「编辑信息 / 设置封面」按钮。

## 🐛 Bug 修复

- **截断静默吞版本**：v1 中「父目录含可执行文件即截断」会让其下版本目录整体消失且没有任何提示。现在被截断且子目录仍有内容时计入扫描告警（判定结果不变，只提供可见性）。
- **启动列表混入未配置版本**：启动按钮下拉原本列出全部版本，导致看起来「所有版本都能启动」。现在只列出已选择启动项的版本，未配置的版本在版本列表中标记「未配启动项」。
- **删除确认失效**：原用系统 `window.confirm`，在 WebView 下被替换为异步对话框，返回值恒为真值——**点取消也会执行删除**。改为应用内确认对话框（`Promise<boolean>` 真正生效），删除档案 / 版本 / 仓库统一走它。
- **封面包角定位**：`.detail-cover` 缺少 `position: relative`，导致「更换封面」角标跑到整个页面右上角，现已贴合封面。

## 📖 升级说明

- **本版不迁移 v1 数据**：`schema_version` 检测到 1 时会 `DROP` 旧业务表后重建（含 `games` / `game_files` 等）。首次启动后既有档案（含手填的名称 / 编号 / 封面）为空，需重新扫描仓库。
- 版本号三处一致：`package.json` / `src-tauri/Cargo.toml` / `src-tauri/tauri.conf.json` 均为 `0.1.0`。
- 新增设置项：`settings.root_excluded_dirs`（仓库根级目录排除名单，JSON 数组，默认含 `#recycle`、`@eaDir`、`$RECYCLE.BIN`、`System Volume Information`、`lost+found`、`.Trash*`、`.DS_Store`）。作废设置项：`max_depth`（v1.1 无深度概念）。

## ⚠️ 已知问题

- **启动功能未实现**：详情页「启动」按钮为占位，点击提示「等待 mvp v2」。
- **手动新建的版本不参与缺失判定**：源目录被删除时不会自动变灰。
- **截断告警（真实仓库 69 条）**：这些目录自身含可执行文件且子目录也有内容，按规则子目录不参与版本识别，可能有版本未被识别——可用「手动新建版本」兜底。
- **详情页 UI 细节残留**：配色 / 间距 / 部分交互反馈留待后续版本迭代。
- **单层枚举的边界**：可执行文件若埋在版本目录的更深层（如 `Ver1.0/bin/sub/game.exe`），不会被自动识别，只能手动配置。

## 📖 使用说明

- **开发运行**：`pnpm tauri dev`（Vite 端口 1421）。
- **打包绿色版**：双击 `build-release.bat` → `release\SakuGame.exe`；`--bundle` 额外生成安装包。
- **首次使用**：设置页 → 添加路径（盘符必填，IP / 主机名可选）→ 点「扫描」→ 主页查看档案。
- **数据位置**：Tauri 应用数据目录下的 `sakugame.db`（SQLite，WAL 模式）。
- **仓库组织**：建议按两层结构组织；不按规范也能建档，只是失去「自动识别同一游戏的多个版本」这一便利，可在扫描后手动归组。
