## 2. 关键实现点（对照决策）

| 决策 | 实现 |
| --- | --- |
| D5 智能下探 / 深度 3 | `walk_dir` 递归，`depth >= max_depth` 停止 |
| D5a 游戏类型落库 | `games.game_type ∈ {folder, archive}`，v1 UI 不展示 |
| D6 分卷聚合 | `.partN.rar` / `.rNN` / `.zNN` / `.7z.001` 四种正则，按组键聚合 |
| D8 进度口径 | 分母 = 顶层条目数，单调不回退 |
| D9 单任务互斥 | `ScanSlot` 单槽 + `ScanBusy` 错误 |
| D10 暂停 / 取消 / 断点 | 暂停落断点、取消清断点、每 50 条自动落断点 |
| D11 幂等重扫 | 只刷新 size/type，**绝不触碰** display_name / game_code / cover_path |
| D12 禁止特化 | 白名单、排除名单、深度均在 `ScanConfig`，可配置 |
| D15 多版本 | 每版本各建一条档案（T32/T33 测试覆盖） |
| D16 三定位项 | `repository_locators` 表 + 按可达性探测（盘符→IP→主机名） |
| D17 目录级粒度 | 同目录多 exe / 多压缩包 = 1 条档案 |
| D18 排除名单只选代表 | 有非名单 exe 就必建档案（T35 测试覆盖） |
| D19 不落库 exe | 库中无任何 exe 字段/表 |
| D20 不留版本字段 | `games` 表无版本相关列 |

## 6. 已知风险

| 风险 | 说明 |
| --- | --- |
| 网络盘探测慢 | `check_repository` 每次真探测，NAS 掉线时可能卡 1-3 秒（SMB 超时） |
| 断点续扫粒度 | 最小单元是顶层条目，单条目内部不可中断（规格允许） |
| 大仓库内存 | 扫描结果全量在内存累积，240 目录规模无问题；上万条目需分批（v2 优化） |
| 中文主机名 | 已实测不可用于 SMB（`\\珱垣的mini终端\资源盘` 不可达），实际只有盘符/IP 生效 |
