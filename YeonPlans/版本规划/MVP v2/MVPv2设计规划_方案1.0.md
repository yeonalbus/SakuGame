## 功能

### 配置缓存池

- 用户在哪用到它：设置 - 仓库管理 - 缓存管理中
- 要看到什么：
	- 路径配置项：用户输入缓存池的路径，且目前仅可配置一个缓存池
	- 缓存池容量显示
	- 缓存池容量配置项：一个输入框、一个单位MB、GB的切换按钮，用户可在此修改缓存池容量
- 要能做什么：
	- 显示当前缓存池剩余容量
	- 缓存池大小默认为10GB，且只接受整数。
	- 当缓存池容量不足时，用户可以扩容。
	- 用户缩容时，不能够低于当前缓存池已经使用的大小
	- 用户扩容时，不能够大于当前磁盘的剩余空间

### 缓存池容量检测

- 用户在哪用到它：
	- 搬运游戏时进行判断
- 要看到什么：
	- 一个提示框。
		- 当搬运的游戏容量>缓存池剩余容量时，提示缓存池容量不足，需要扩容。
		- ~~当搬运的游戏容量<缓存池剩余容量&&搬运的游戏容量>磁盘剩余空间时，提示磁盘容量不足~~
		- if (game_size > pool_free)  → 缓存池配额不足（提示扩容/清理）
			else if (game_size > disk_free) → 缓存池所在卷物理空间不足
			if (pool_root 未配置)       → 搬运按钮禁用（方案未写这条）
- 要能做什么：
	- 暂停搬运。当用户手动删除掉缓存池的游戏，或者扩容缓存池容量后，即可点击恢复任务，恢复任务时再进行一遍检测，检测通过后则正常搬运，否则仍然提醒用户并阻塞任务
	- mvpv2不要做自动移除功能，仅能用户手动清理，这个是mvpv3做的事
	- 解压型游戏**边解压边校验剩余空间，超限即中止并回滚已解压部分**。

### 搬运游戏

- 用户在哪用到它：
	- 游戏没有在本地缓存池的时候，在详情界面显示
- 要看到什么：
	- 详情界面中按钮的“启动：”文案更改为“搬运：”
	- 同时在按钮上显示一个搬运进度条，显示搬运进度
- 要能做什么：
	- 区分游戏版本，每个游戏版本单独占有一个搬运态。
		- 例如用户点击了“搬运：V1”，并且选择的是V1版本，此时在按钮上显示一个搬运进度条。当搬运完成后，文案改为“启动：V1”
		- 而如果用户此时切换到了“V2”，则文案是“搬运：V2”，且在用户没有点击“搬运：V2"，即V2没有启动搬运任务的情况下，不显示搬运进度条。V2启动了搬运任务后，它的进度条和V1是独立的
	- 搬运方案：
		- 搬运到缓存池中，文件夹格式为：
			- 标准型：缓存池根/游戏标识层/搬运对象
			- 紧凑型：缓存池根/搬运对象
		- 如果搬运的是压缩包类型，则需要进行解压操作。边界条件详见**MVPv2设计规划_定义1.0**

### 配置补丁

- 用户在哪用到它：
	- 在游戏详情页-版本管理-变更组配置
	- 在设置-仓库管理-变更组路径
- 要看到什么：
	- 设置-仓库管理-变更组路径提供一个输入框，用户在此配置变更组的根路径
	- 游戏详情页-版本管理-变更组配置中，可以选择是否启用补丁，并且显示该版本对应的补丁路径
		- 启用补丁的时候，可以选择是否配置注入补丁后的启动项。
- 要能做什么：
	- 先将游戏搬运到缓存池中，再注入存档，最后注入补丁
	- 当配置了注入补丁后的启动项时，采用新的启动项，而不是建档时的可执行文件
	- 补丁文件存储在变更组根路径/patch/游戏标识层/版本标识层/补丁文件，如果是紧凑型配置，则将版本标识层记录为“sakucompact”
### 配置存档

- 用户在哪用到它：
	- 在游戏详情页-版本管理-变更组配置
	- 在设置-仓库管理-存档组路径
- 要看到什么：
	- 游戏详情页-版本管理-变更组配置中，显示该版本对应的存档路径。存档必然注入，不能选择是否启用
- 要能做什么：
	- 先将游戏搬运到缓存池中，再注入存档
	- 存档文件存储在变更组根路径/save/游戏标识层/版本标识层/补丁文件，如果是紧凑型配置，则将版本标识层记录为“sakucompact”
### 启动游戏

- 用户在哪用到它：
	- 游戏详情页的启动按钮
- 要看到什么：
	- “启动：XXX”的文案（已在mvp v1.1实现）
- 要能做什么：
	- 点击启动后，通过配置的启动项拉起游戏进程。
	- 不需要做关闭游戏进程，只需要负责拉起即可
