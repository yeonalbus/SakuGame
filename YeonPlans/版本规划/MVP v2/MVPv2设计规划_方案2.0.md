## 功能

### 配置缓存池

- 用户在哪用到它：设置 - 仓库管理 - 缓存管理中
- 要看到什么：
	- 路径配置项：用户输入缓存池的路径，且目前仅可配置一个缓存池
	- 缓存池容量显示
	- 缓存池容量配置项：一个输入框、一个单位MB、GB的切换按钮，用户可在此修改缓存池容量
- 要能做什么：
	- 显示当前缓存池剩余容量
	- 缓存池大小默认为10GB，且只接受整数。
	- 当缓存池容量不足时，用户可以扩容。
	- 用户缩容时，不能够低于当前缓存池已经使用的大小
	- 用户扩容时，不能够大于缓存池所在磁盘的剩余空间

### 缓存池容量检测

- 用户在哪用到它：
	- 搬运游戏时进行判断
- 要看到什么：
	- 一个提示框。
		- 当搬运的游戏容量>缓存池剩余容量时，提示缓存池容量不足，需要扩容。
		- ~~当搬运的游戏容量<缓存池剩余容量&&搬运的游戏容量>磁盘剩余空间时，提示磁盘容量不足~~
		- if (game_size > pool_free)  → 缓存池配额不足（提示扩容/清理）
			else if (game_size > disk_free) → 缓存池所在卷物理空间不足
			if (pool_root 未配置)       → 搬运按钮禁用
- 要能做什么：
	- 暂停搬运。当用户手动删除掉缓存池的游戏，或者扩容缓存池容量后，即可点击恢复任务，恢复任务时再进行一遍检测，检测通过后则正常搬运，否则仍然提醒用户并阻塞任务
	- mvpv2不要做自动移除功能，仅能用户手动清理，这个是mvpv3做的事
	- 解压型游戏**边解压边校验剩余空间，超限即中止并回滚已解压部分**。

### 搬运游戏

- 用户在哪用到它：
	- 游戏没有在本地缓存池的时候，在详情界面显示
- 要看到什么：
	- 详情界面中按钮的“启动：XXX”文案更改为“搬运：XXX”
	- 当点击了“搬运：XXX”后，将会启动搬运。此时给出暂停、取消按钮。
	  同时在“搬运：XXX”按钮下方显示一个小搬运进度条，显示搬运进度
- 要能做什么：
	- 区分游戏版本，每个游戏版本单独占有一个搬运态。
		- 例如用户点击了“搬运：V1”，并且选择的是V1版本，此时在按钮上显示一个搬运进度条。当搬运完成后，文案改为“启动：V1”
		- 而如果用户此时切换到了“V2”，则文案是“搬运：V2”，且在用户没有点击“搬运：V2"，即V2没有启动搬运任务的情况下，不显示搬运进度条。V2启动了搬运任务后，它的进度条和V1是独立的
	- 搬运方案：
		- 搬运到缓存池中，文件夹格式为：
			- 标准型：缓存池根/游戏标识层/搬运对象
			- 紧凑型：缓存池根/搬运对象
		- 如果搬运的是压缩包类型，则需要进行解压操作。边界条件详见**MVPv2设计规划_定义1.0**

### 搬运机

- 用户在哪用到它：详情页「搬运：XXX」按钮、左侧导航「搬运」页
- 要能做什么：
	1. **队列**：全局动态通道，上限并发数为32，如果当前任务没有占用所有的并发数，则可以从排队队列中调入任务，调入任务前需要确认调入后是否会超过并发数，若不超过则开始搬运，其余排队。任务身份 = `(游戏标识, 版本标识)`，同游戏不同版本各自独立。
	2. **状态**：排队中 / 搬运中 / 暂停中 / 出错 / 完成。搬运中可暂停、取消；出错可重试；暂停可恢复。
	3. **并发**：按该版本待搬文件数自动定档——≤200 用 4，201–2000 用 8，2001–10000 用 16，>10000 用 32，上限 32。内部策略，不给用户调。
	4. **写入磁盘**：一律先写 `缓存池根/.staging/<任务id>/`，校验通过后整体改名到最终路径。缓存池内不会出现半成品；中断、取消、崩溃也都不留脏目录。
	5. **容量预检**：点搬运即时判——池未配置 → 按钮禁用；游戏体积 > 池剩余配额 → 提示配额不足；> 所在卷剩余空间 → 提示磁盘不足。不通过不进队列。**恢复任务前重跑一次**。
	6. **解压型**：搬运单元顶层有压缩包即为解压型。搬完压缩包后解压，边解压边查剩余空间，不足则中止、删掉已解压部分、转「暂停中」提示扩容；解压完成后删掉 staging 内的压缩包副本，只留解压产物。顶层存在多个压缩包 → 判定形态不规范，直接禁止搬运。
	7. **暂停 / 取消**：暂停在文件边界生效，已写部分保留；恢复按已存在文件跳过续传；取消删除整个 staging，回滚干净。
	8. **失败**：单文件重试 2 次，仍失败则记入失败清单继续搬其余文件；搬完转「出错」并列出失败项。源仓库不可达 → 提示并保留现场，不自动无限重试。
	9. **进度**：按字节算，ETA 用最近 10 秒窗口平滑，刷新节流 200 ms。
	10. **搬运态 → 完成**：staging 内文件全部写完 → L1 校验（文件数 + 总字节 + 逐文件 size）→ 原子 rename → 写缓存记录。
- 要看到什么
	- 搬运页按状态分组列出：游戏名 + 版本标识、体积、进度条、速率、ETA、暂停/恢复/取消/重试。
	- 详情页按钮下方一条小进度条，完成后文案变「启动：XXX」。
	- 两处状态与数字实时一致。

### 启动游戏

- 用户在哪用到它：
	- 游戏详情页的启动按钮
- 要看到什么：
	- “启动：XXX”的文案（已在mvp v1.1实现）
- 要能做什么：
	- 点击启动后，通过配置的启动项拉起游戏进程。
	- 不需要做关闭游戏进程，只需要负责拉起即可

## UI设计

### 配置缓存池：

设置 - 仓库管理 ：分为上下两部分，上面显示缓存管理，下面显示仓库路径
缓存管理区域需要显示变更组路径配置、缓存路径配置，以及缓存池容量图
仓库路径显示现在的扫描进度条、仓库路径配置条目

### 详情页优化

将现在的版本条目分为左右两部分，
右边显示现在的内容
左边显示变更组配置条目

### 搬运任务页面：

显示在左侧导航栏，主页和设置之间，即变成主页/搬运/设置
用于显示正在搬运的任务队列，分为搬运中，排队中，暂停中，出错，搬运完成
