
> [!NOTE] 变更内容
> 1、经过讨论，取消对压缩包形态的支持。现有实现进行降级，压缩包形态的版本在详情页显示『压缩包形态 · 未就绪，请解压后重扫』，搬运按钮禁用
> 2、缓存池路径新增「仓库编号」分层：标准型为 `缓存池根/仓库编号/游戏标识层/搬运对象`，紧凑型为 `缓存池根/仓库编号/游戏标识层/SakuCompact/`
> 3、容量口径明确：已用 = 已完成缓存 + 进行中任务已写入 + 预留；预检通过即计入已用，取消/失败归还；缩容不低于已用；扩容需满足「新配额 − 已用 ≤ 盘剩余 − 盘总容量×10%」
> 4、新增「从缓存池移除」手动清理入口（v2 仅手动，不做自动淘汰）
> 5、缓存池路径约束：不得设在任何仓库根之内；有缓存或有任务（含排队中）时禁止修改路径
> 6、仓库删除时连带清理其在缓存池中的文件；删库再加回会分配新编号，旧缓存需重搬
> 7、启动已缓存游戏不依赖仓库可达（NAS 断电不影响启动）
> 8、任务生命周期：程序启动时检测未完成任务并转「暂停中」，staging 保留可续传
> 9、明确不做从缓存池往 HDD 写入的操作，「本地放置游戏 → 往仓库搬运」不在 v2 范围
> 10、取消详情页左右分栏与变更组配置的 UI 改动，留待 2.1
> 11、未配置启动项时，启动按钮显示「配置启动项」

## 功能

### 配置缓存池

- 用户在哪用到它：设置 - 仓库管理 - 缓存管理中
- 要看到什么：
	- 路径配置项：用户输入缓存池的路径，且目前仅可配置一个缓存池
	- 缓存池容量显示
	- 缓存池容量配置项：一个输入框、一个单位MB、GB的切换按钮，用户可在此修改缓存池容量
- 要能做什么：
	- 显示当前缓存池剩余容量
	- 缓存池大小默认为10GB，且只接受整数。
	- 当缓存池容量不足时，用户可以扩容。
	- 用户缩容时，不能够低于当前缓存池已用的大小，已用 = 已完成缓存 + 进行中任务已写入
	- 用户扩容时，需满足「新配额 − 已用 ≤ 盘剩余空间 − 盘总容量×10%」，即扩容后盘上至少留出盘总容量 10% 的余量
- 边界条件：
	- 缓存池路径不得设在任何仓库根之内

### 缓存池容量检测

- 用户在哪用到它：
	- 搬运游戏时进行判断
- 要看到什么：
	- 一个提示框。
		- 判断（按顺序）：
			- 池未配置 → 搬运按钮禁用
			- game_size > 池剩余配额 → 配额不足（提示扩容/清理）
			- game_size > 可用空间 → 物理空间不足
		- 变量定义：可用空间 = 盘剩余空间 − 盘总容量×10%
		- 记账：预检通过 → game_size 记入已用（预留）；任务取消/失败 → 归还

- 要能做什么：
	- 暂停搬运。当用户从缓存池移除其他游戏，或者扩容缓存池容量后，即可点击恢复任务，恢复任务时再进行一遍检测，检测通过后则正常搬运，否则仍然提醒用户并阻塞任务
	- mvpv2不做自动淘汰/自动释放空间
	- 有缓存时或有任务时禁止改路径，提示用户先手动删除
		- 任务包含：搬运中的任务、 暂停中已经被搬运了一部分的任务、排队中的任务
		- 有缓存判定：一打开设置页就判——池内有已完成缓存（或有任务）→ **路径输入框直接灰色禁用**，旁边写一句「请先清空缓存池再修改路径」。用户一眼知道为什么不能改
### 清理游戏

- 用户在哪用到它：详情页「从缓存池移除」按钮
- 要能做什么：
	- 用户点击了按钮后，会弹出警告框告知用户会删除缓存池内的副本，仓库中文件不受影响
	- 用户点击确认后，直接删除掉这个游戏在缓存池中的副本，删除时不做回写（回写属 V2.1 变更组功能），池内产生的改动直接丢弃。删除后：缓存记录清除 → 容量归还 → 详情页按钮回到「搬运：XXX」
	- 用户点击取消后，则不进行删除
- 要看到什么：
	- 在版本下拉栏的条目的右侧显示一个删除按钮，游戏没有在缓存池中的时候低亮度，游戏在缓存池中的时候正常亮度。鼠标悬浮时会显示“从缓存池移除版本”。
	- 弹出警告框，警告框上有确认和取消两个按钮
- 边界条件：
	- 游戏版本正在被搬运的时候，该版本无法被删除掉，只能取消搬运。

### 搬运游戏

- 用户在哪用到它：
	- 游戏没有在本地缓存池的时候，在详情界面显示
- 要看到什么：
	- 详情界面中按钮的“启动：XXX”文案更改为“搬运：XXX”
	- 当点击了“搬运：XXX”后，将会启动搬运。此时给出暂停、取消按钮。
	  同时在“搬运：XXX”按钮下方显示一个小搬运进度条，显示搬运进度
	- 压缩包形态版本 → 详情页显示「未就绪，请解压后重扫」
- 要能做什么：
	- 区分游戏版本，每个游戏版本单独占有一个搬运态。
		- 例如用户点击了“搬运：V1”，并且选择的是V1版本，此时在按钮上显示一个搬运进度条。当搬运完成后，文案改为“启动：V1”
		- 而如果用户此时切换到了“V2”，则文案是“搬运：V2”，且在用户没有点击“搬运：V2"，即V2没有启动搬运任务的情况下，不显示搬运进度条。V2启动了搬运任务后，它的进度条和V1是独立的
	- 区分来源仓库：每个仓库赋予一个编号，作为缓存池路径的一层
	- 搬运方案：
		- 搬运到缓存池中，文件夹格式为：
			- 标准型：缓存池根/仓库编号/游戏标识层/搬运对象
			- 紧凑型：缓存池根/仓库编号/游戏标识层/SakuCompact/（内容即该版本文件）

### 搬运机

- 用户在哪用到它：详情页「搬运：XXX」按钮、左侧导航「搬运」页
- 要能做什么：
	1. **队列**：全局动态通道，上限并发数为32，如果当前任务没有占用所有的并发数，则可以从排队队列中调入任务，调入任务前需要确认调入后是否会超过并发数，若不超过则开始搬运，其余排队。任务身份 = `(仓库编号, 游戏标识, 版本标识)`，不同仓库的同名游戏的不同版本，或是同一仓库的同一游戏下的不同版本各自独立。
	2. **状态**：排队中 / 搬运中 / 暂停中 / 出错 / 完成。搬运中可暂停、取消；出错可重试；暂停可恢复。
	3. **并发**：按该版本待搬文件数自动定档——≤200 用 4，201–2000 用 8，2001–10000 用 16，>10000 用 32，上限 32。内部策略，不给用户调。
	4. **写入磁盘**：一律先写 `缓存池根/.staging/<任务id>/`，校验通过后整体改名到最终路径。缓存池内不会出现半成品；中断、取消、崩溃也都不留脏目录。
	5. **容量预检**：池未配置 → 按钮禁用；游戏体积 > 池剩余配额 → 提示配额不足；> 可用空间（卷剩余 − 盘总容量×10%）→ 提示磁盘不足。不通过不进队列。**恢复任务前重跑一次**。
		- 判定时机：
			- 预检通过的那一瞬间，把任务字节计入「已用」（预留）；任务取消/失败时归还
			- 开搬前再判一次（防排队期间盘被占）
			- 安全线参与所有判盘
	6. **暂停 / 取消**：暂停在文件边界生效，已写部分保留；恢复按已存在文件跳过续传；取消删除整个 staging，回滚干净。
	7. **失败**：单文件重试 2 次，仍失败则记入失败清单继续搬其余文件；搬完转「出错」并列出失败项。源仓库不可达 → 提示并保留现场，不自动无限重试。
	8. **进度**：按字节算，ETA 用最近 10 秒窗口平滑，刷新节流 200 ms。
	9. **搬运态 → 完成**：staging 内文件全部写完 → L1 校验（文件数 + 总字节 + 逐文件 size）→ 原子 rename → 写缓存记录。
- 要看到什么
	- 搬运页按状态分组列出：游戏名 + 版本标识、体积、进度条、速率、ETA、暂停/恢复/取消/重试。
	- 详情页按钮下方一条小进度条，完成后文案变「启动：XXX」。
	- 两处状态与数字实时一致。
- 边界条件：
	- **程序启动时**检测到未完成任务 → 转「暂停中」，staging 保留，手动恢复续传
	- 暂停粒度为文件边界，单个大文件要等该文件写完

### 启动游戏

- 用户在哪用到它：
	- 游戏详情页的启动按钮
- 要看到什么：
	- “启动：XXX”的文案（已在mvp v1.1实现），未配置启动项时显示「配置启动项」
- 要能做什么：
	- 点击启动后，通过配置的启动项拉起游戏进程。
	- 不需要做关闭游戏进程，只需要负责拉起即可
	- 启动已缓存的游戏不依赖仓库可达

### 完善仓库删除

- 删除仓库时，同样会清理掉仓库在缓存池中所拥有的路径下的所有文件
	- 删除前应**提示池内涉及数量与体积**（「该仓库有 3 个游戏在缓存池，占用 26.4 GB，将一并删除」）
	- 有进行中/排队任务时则必须先把任务取消，再删库。否则任务还在往一个正在被删的路径里写
- 删了仓库再加回来时，编号会变，则旧缓存要重搬
	- 这个同样符合设计思路，删库会直接导致档案被删除，因此并不需要专门去保留缓存池文件

## ACC

### 缓存池配置
- [ ] 可在 设置-仓库管理 配置缓存池路径；路径设在任一仓库根内时拒绝并提示
- [ ] 容量默认 10GB、只接受整数；MB/GB 单位可切换且换算正确
- [ ] 缓存管理区显示环形容量图与已用/剩余数字
- [ ] 缩容时，新配额低于「已用」（已完成缓存 + 进行中已写入 + 预留）则拒绝
- [ ] 扩容后盘上余量不足「盘总容量 10%」则拒绝
- [ ] 有已完成缓存、或有任务（含排队中）时，路径输入框禁用并提示

### 容量预检
- [ ] 池未配置时搬运按钮禁用
- [ ] 配额不足、物理空间不足分别给出对应提示
- [ ] 预检通过即占用配额：连点两个总量超配额的游戏，第二个被拦截
- [ ] 预检不通过不进队列；恢复任务前重判；开搬前再判

### 搬运
- [ ] 池内落点符合 `池/仓库编号/游戏标识层/搬运对象`，紧凑型为 `…/游戏标识层/SakuCompact/`
- [ ] 搬运中可暂停（文件边界生效）、恢复（跳过已存在文件）、取消（清 staging 回滚干净）
- [ ] 全局并发上限 32，按待搬文件数自动定档 4/8/16/32，超限排队
- [ ] 搬运页按 5 状态分组，显示进度/速率/ETA，与详情页数字一致
- [ ] 完成后按钮变「启动：XXX」；L1 校验不通过不执行 rename
- [ ] 程序重启后未完成任务为「暂停中」，可恢复续传

### 清理
- [ ] 版本条目右侧「从缓存池移除」：未缓存时灰显，缓存中正常亮度
- [ ] 搬运中的版本不可删除，提示先取消
- [ ] 移除后：缓存记录清除 → 容量归还 → 详情页按钮回到「搬运：XXX」

### 启动
- [ ] 已缓存游戏在仓库不可达（NAS 断电）时仍能启动
- [ ] 压缩包形态版本显示「未就绪，请解压后重扫」，搬运禁用

### 仓库
- [ ] 删除仓库时清理该仓库在池内的文件，删除前提示涉及数量与体积
- [ ] 删除仓库前，该仓库在途任务已取消
