## 三、用户可感知亮点

### A. 现在真的能玩了

- 点游戏 → 容量预检 → 自动从 NAS 搬到本地 SSD → 直接启动，全程不用手开文件管理器
- 游戏从缓存池路径运行，**NAS 断电、断网都不影响已搬过来的游戏**
- 搬运有进度、速率、ETA，可暂停 / 继续（断点续传）/ 取消
- 新页面「搬运」集中管理所有搬运与回写任务

### B. 存档不再需要整包搬运

- 玩完点「移出缓存」，程序**只把改动过的文件**写回 NAS，不整包覆盖
- 游戏本体的变更按基线判断（没动过的不回写），用户目录的变更按「是否已入库」判断（可能在任何位置的存档一律列出让你选）
- 必须回写的文件（旧存档被覆盖）会红色标注且不可取消，其余由你勾选
- **安全兜底**：用户路径没配或不可达时，宁可报错回滚也不静默跳过——不会悄悄丢掉存档
- 崩溃 / 断电不怕：下次启动会读暂存清单自动续写完成

### C. 缓存管理终于看得见

- 缓存池有环形占用图，显示已用 / 配额 / 盘剩余 / 安全线
- 容量是逻辑配额，不预分配磁盘
- 仓库删除前会提示该仓库在池内占了多少

### D. 其它修复

- 版本大小不再显示偏小（此前 303 MB 实际 5.79 GB）
- 仓库编号不再跳号（删过仓库后不再出现 R02、R03）
- 游戏文件夹在 NAS 里被移动后，不再需要重新扫描，程序靠锚点自动找回

## 四、升级注意

- **平滑迁移**：启动时自动把 schema v2 升到 v5，手填数据全部保留
- **既有仓库建议重新扫描一次**：才能补出 `.SakuAnchor.json`（获得跳过重扫与移动重定位能力）
- **压缩包版本需先在仓库解压**：压缩包形态不再可搬运
- **新增设置项**：缓存池路径与容量（默认 10 GB）、版本级用户路径（可留空）
- **唯一要注意的破坏性场景**：从很早的开发期构建（v1 数据库）升级会清空业务表——正式用 0.1.0 的用户不受影响

## 五、已知问题（如实）

- 缓存池满时**不会自动淘汰**，需手动移出缓存（设计选择：移出要人工确认存档回写）
- 不跟踪游戏进程，存档变更只在点「移出缓存」时检测
- **没有池内游戏列表**，也**没有「上次游玩时间」**——池里有什么需进详情页看
- **没有搜索与筛选**，游戏多了只能滚动找
- 封面与元数据需手填（不抓 DLsite / FANZA）
- 不支持多变更组备份（单变更组）
- 崩溃恢复 / 回写抢占 / 紧凑型全流程已实现但无自动化回归测试；主路径已实机验证
- 详情页 UI 仍有细节残留（配色 / 间距 / 交互反馈）
