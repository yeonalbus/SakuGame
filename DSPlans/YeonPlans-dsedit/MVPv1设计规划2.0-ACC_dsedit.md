## 0. 使用说明

### 0.1 判定原则

| 原则 | 内容 | 出处 |
| --- | --- | --- |
| **一票否决** | 「不漏档」不达标即验收失败，不得以"误报少"或"完成度高"替代 | 主人第四轮："绝对不能漏掉正确的，但可以接受误判错误的" |
| **可判定** | 每条验收项必须能用"通过 / 不通过"回答，不接受"基本正常"这类描述 | 规划写作指南 L6 |
| **可复现** | 每条附判定方法，任何人按方法执行可得到相同结论 | 同上 |
| **分层执行** | 自动化（A）→ 结构校验（S）→ 人工核对（M）；M 类需主人亲自确认 | 本源 |

### 0.2 判定方法与代号

| 代号 | 含义 | 执行者 |
| --- | --- | --- |
| **A** | 自动化测试（Rust 侧集成测试，自动构造临时目录树并断言） | 实现侧 |
| **S** | 静态校验（数据库 schema / 代码审查 / 配置检查） | 实现侧 |
| **M** | 人工核对（目视 UI、抽样比对真实仓库、主观体验判断） | **主人** |

### 0.3 编号规则

`ACC-<模块>-<序号>`，模块取 2.0 规划中的功能编号：

| 模块 | 对应 2.0 |
| --- | --- |
| `DFC-01` | 多仓库路径配置 |
| `DFC-02` | 自动扫描可执行文件 |
| `DFC-04` | 建档 |
| `DUI-01/02/03` | 导航栏 / 主页与详情页 / 设置页 |
| `CON` | 约束性验收（"不该做的事"是否真的没做） |
| `PERF` | 性能 |
| `ERR` | 异常处理 |

## 2. ACC-DFC-01 多仓库路径配置

| # | 验收项 | 判定方法 | 依据 |
| --- | --- | --- | --- |
| **ACC-01-01** | 可添加一个仓库路径，添加后出现在仓库列表中 | M | DFC-01 |

| **ACC-01-08** | 三个已配置定位项**全部不可达**时，明确提示"检查网络配置"，且仓库标记为离线 | A + M | D16 |
| **ACC-01-09** | 定位项切换（如盘符失效改走 IP）后，档案**仍可正常访问**，无需重新扫描 | A | D16、O3 |

| **ACC-02-02** | 目录名为**游戏编号**（`RJ01005841`）、exe 名与目录名**毫无关联** → 必定建档 | A（T25） | 实测：强命中 0/240 |

| **ACC-02-06** | 多版本结构（`RJ1234/Ver1.0`、`RJ1234/Ver2.0`）→ **每个版本各建一条**档案（不聚合） | A（T32、T33） | D15 |

## 10. 验收流程

```text
阶段 1（实现侧）  运行全部 A 类用例（T1–T35 覆盖）+ S 类结构校验
                  ↓ 必须 100% 通过
阶段 2（实现侧）  在 Z:/Game 上执行扫描，导出：
                    · 建档清单（含类型、大小、相对路径）
                    · 误报清单（误建为档案的非游戏目录）
                    · 漏档自查清单
                  ↓
阶段 3（主人）    以基准清单比对：漏档必须为 0；误报抽查确认可接受
                  ↓ 通过
阶段 4（主人）    目视 UI 验收（ACC-DUI 组、进度体验）
                  ↓ 通过
结论              v1 验收通过
```
